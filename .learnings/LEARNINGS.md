# 项目经验

## 2026-11-17：Dot 接入边界

- 状态：resolved
- Dot 网页消息和云端任务查询有不同的地址与生命周期。任务查询失败不应把已收到的聊天回复判为失败；关闭本地连接也不代表远端工作停止。
- 新增引擎除更新 EngineId，还需检查通道换算、默认来源、图标和平台协议过滤，否则类型检查通过后仍可能在菜单中无法选择或误入模型网关。
- EngineHost 的公开清理方法是 shutdown()，同步白名单方法是 syncableSettings()；联调测试应先核对公开接口，避免 finally 的错误掩盖原始断言。
- 定向测试先读对应包的 scripts：桌面 test 脚本自带多个源码目录，追加单文件仍会跑全量，应使用 `pnpm --filter @pixelsky/desktop exec vitest run <文件>`。仓库 scripts/check.mjs 配置了适合进程测试的 20 秒超时，可使用 --only 选择相关检查。

## 2026-11-17：Dot 通道入口和账号共享

- 状态：resolved
- 用户纠正：仅增加后端和模型菜单不算完成入口；新增通道必须在「设置 → 模型通道」的卡片列表中实际渲染，并对安装包做界面验证。
- Dot 与 Codex 共用 ChatGPT 登录、账号列表和持久化。通过现有 app-server 读取和刷新令牌，不能要求用户另填 token，也不能复制一份凭据到 Dot 设置。
- 账号变化时，旧 Dot 房间不能继续用新账号发请求；请求使用的凭据与已验证房间身份必须一致。
- Dot 动态入口按“已保存账号 + 远端 Dot”绑定，不能用全局当前账号替代。2026-11-18 用户更新要求：在主窗口右侧对话区打开，替代此前独立窗口设计。
- 用户明确的套餐显示规则：只显示 Pro / prolite / promax，Plus 不显示且不查询 Dot 目录。

## 2026-11-17：Dot 默认账号、房间身份和打包样式

- 状态：resolved
- 默认 Codex 账号可由 `HostAccounts.list()` 动态返回，不一定存在于保存清单。解析已保存账号目录时必须兼容这个默认账号，同时继续拒绝隐藏或未知 ID。
- 真实 Dot 房间的人类成员可能使用 `chatgpt_user_id`，与令牌中的 `chatgpt_account_user_id` 不同。只在两个可信声明中核对实际成员，发送回执继续使用验证得到的成员 ID。
- 用户反馈安装后的 Dot 窗口只有裸文本。Vite 8 对 `await (条件 ? import(A) : import(B))` 生成的预加载依赖只覆盖一个分支，导致另一个入口的 CSS 没加载。入口改用独立 if/else 导入，并检查构建后各分支的 CSS 依赖和安装版界面。
- Dot 历史消息内的公开签名 URL 会过期并返回 404；2026-11-18 已改为先按同一房间的文件 ID 刷新下载地址，再由主进程下载，不能只靠放宽 CSP 修复预览。

## 2026-11-18：Dot 404 恢复与客户端交互

- 状态：resolved（针对性测试通过，安装交互验收记录在 TODO）。
- 安装日志确认 `dotChat:read` 的 404 来自 `/tbo/by-thread/{thread}`；同一账号和 Dot 的稳定 ID 查询可返回有效 profile。线程索引 404 时仅恢复同一 Dot 的当前线程，并继续核验房间和成员；禁止回退到其它 primary Dot。
- Electron 的认证 GET 显式禁用缓存和 Cookie，避免窗口共享的缓存或网页登录影响保存账号的 OAuth 请求。POST 不自动重试。
- 文件、图片预览及 Dot 电脑入口应直接连接客户端能力；链接到网页不能视为这些交互已实现。真实 API 只读成功、有效 SDP 应答和客户端交互验收应分开记录。
- 用户最新界面要求：沿用像素星空正常对话设计，共用阅读列、输入卡片和主题；不能只按源码中存在 CSS 就判断 UI 已完成。
